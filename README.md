# Nawy Design System

مرجع التصميم الرسمي لمنتجات **ناوي**. الهدف هو أن تبدو منتجات Nawy كعائلة واحدة واضحة ومتسقة، مع الاحتفاظ بحرية كل منتج في بناء تجربة تناسب وظيفته.

> **المبدأ:** هوية مشتركة، وتجارب متخصصة. لا نحول كل التطبيقات إلى واجهة واحدة ولا ننسخ مكونات لا تناسب سياق المنتج.

## حالة الإصدار

- الإصدار: **0.1.0 — Foundation**
- الحالة: تأسيس أولي؛ بعض القيم البصرية التشغيلية مقترحة وتحتاج مراجعة على شاشات المنتجات الفعلية.
- اللغة الأساسية للتوثيق: العربية، مع أسماء تقنية إنجليزية عند الحاجة.
- اتجاه الواجهات الافتراضي: RTL للعربية، مع دعم LTR للإنجليزية.

## من أين تبدأ؟

1. اقرأ [دليل النظام](DESIGN-SYSTEM.md).
2. راجع [الأساسيات البصرية](foundations/README.md).
3. استخدم [Design Tokens](tokens/tokens.css) و[JSON Tokens](tokens/tokens.json) بدل تكرار القيم داخل التطبيقات.
4. اتبع [قواعد الوكلاء وأدوات Vibe Coding](AI-GUIDELINES.md) قبل توليد أو تعديل الواجهات.
5. استخدم [مكتبة المكونات](components/README.md) و[أنماط التجربة](patterns/README.md) كمرجع، لا كقوالب جامدة.

## قواعد غير قابلة للتفاوض

- البساطة والوضوح وسهولة الاستخدام قبل الزخرفة.
- لا تُدخل لونًا أو خطًا أو مكونًا جديدًا لمجرد أنه رائج.
- احترم RTL/LTR باستخدام الخصائص المنطقية في CSS، لا ترقيع الاتجاهات يدويًا.
- لا تجعل اللون الوسيلة الوحيدة لنقل الحالة أو المعنى.
- لا تضف وعودًا أو ادعاءات خصوصية أو تخزين لا يحققها التطبيق نفسه.
- لا تفرض مواعيد أو تذكيرات أو تصنيفات أو لوحات معلومات على منتج لا يحتاجها.
- حافظ على الوصول بلوحة المفاتيح، وتباين النصوص، ومناطق لمس مناسبة.

## نطاق النظام

هذا المستودع يحدد الهوية المشتركة، الأساسيات، المبادئ، والأنماط العامة. يظل لكل منتج ملف قرارات خاص به عند الحاجة، بشرط ألا يناقض الأساس المشترك دون توثيق.

## المساهمة والتغيير

أي تغيير في اللون الأساسي أو الخط أو الشعار أو سلوك مكون مشترك يجب أن:
1. يوضح المشكلة التي يحلها.
2. يراجع أثره على المنتجات الحالية واللغتين.
3. يحدث ملفات التوثيق وملفات tokens في التغيير نفسه.
4. يسجل في [CHANGELOG.md](CHANGELOG.md).

لا تعتبر القيم الموسومة **Proposed** نهائية قبل اختبارها واعتمادها.
