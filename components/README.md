# Components — المكونات

هذا الملف يحدد مبادئ المكونات المشتركة. لا توجد حاليًا مكتبة UI برمجية مفروضة؛ يمكن تنفيذ المكونات بالتقنية المناسبة لكل منتج مع الحفاظ على السلوك واللغة البصرية.

## Icon System — نظام الأيقونات

**الاختيار الافتراضي لناوي: Google Material Symbols بصيغة SVG، بأسلوب Outlined.**

- المصدر الأساسي: [Google Material Design Icons repository](https://github.com/google/material-design-icons).
- معرض الاختيار: [Google Fonts — Material Symbols](https://fonts.google.com/icons).
- اختر ملفات SVG الفعلية من المسار `symbols/web/<icon-name>/materialsymbolsoutlined/<icon-name>_24px.svg`.
- الترخيص: Apache License 2.0. احتفظ بنسخة الترخيص والإسناد مع الأصول المنقولة عند توزيعها.
- مقاس التصميم الافتراضي: 24×24، مع الحفاظ على viewBox الأصلي.
- اللون: أحادي اللون ويأخذ لون الواجهة عبر `currentColor` أو CSS inheritance عند تحويل SVG إلى React component.
- حالات selected/active يمكن استخدام نسخة fill من نفس الرمز عندما تكون متاحة؛ لا تخلط أساليب مختلفة.
- في React + Vite يمكن استيراد SVG كمكون عبر `vite-plugin-svgr` واستخدام `?react`.

### قواعد إلزامية

- ممنوع استخدام Emoji أو رموز Unicode التعبيرية كبديل لأيقونات الواجهة، بما في ذلك رموز واتساب أو حزم Emoji عشوائية.
- لا تستخدم صور PNG أو لقطات شاشة أو SVG مجهول المصدر للأيقونات الوظيفية.
- لا تستخدم أيقونات مولدة بالذكاء الاصطناعي كبديل لمجموعة واجهة متسقة.
- لا تخلط مكتبات أيقونات مختلفة في الشاشة الواحدة. لا تستخدم Lucide كخيار افتراضي.
- إذا لم يوجد رمز مفهوم ومناسب، استخدم تسمية نصية واضحة بدل اختراع رمز مربك.
- شعارات الخدمات والشركات ليست أيقونات Material؛ استخدم الأصول الرسمية الخاصة بكل علامة واحترم ترخيصها.
- لا تعدّل المسارات أو النسب لتغيير معنى الرمز. التعديل التقني اللازم للون أو الحجم مقبول، وأي تعديل بصري جوهري يحتاج توثيقًا.
- سمِّ ملفات الأيقونات بأسمائها الدلالية الأصلية، واجعل قائمة الأيقونات المستخدمة واضحة داخل المشروع.

### الإتاحة

- الرمز الزخرفي بجوار نص واضح: `aria-hidden="true"`.
- زر أيقونة بلا نص ظاهر: وفر `aria-label` واضحًا على الزر نفسه.
- لا تضع اسم الأيقونة وحده في DOM على أنه نص مقروء.
- تأكد من وضوح الرمز في الثيمين وأحجامه الصغيرة.

## Button

- الأنواع: Primary، Secondary، Tertiary/Ghost، Destructive عند الحاجة.
- الأحجام: Small، Medium، Large وفق احتياج المنتج.
- الحالات: default، hover، focus-visible، pressed، disabled، loading.
- استخدم نصًا فعليًا يوضح الإجراء.
- لا تستخدم زرًا لفتح رابط خارجي؛ استخدم link.

## Text Field & Text Area

- label واضح خارج placeholder.
- حالات: default، focus، filled، error، disabled، read-only.
- اعرض الخطأ قرب الحقل، واشرح طريقة إصلاحه.
- حدد type وautocomplete وinputmode عند ملاءمتها.
- تعامل مع RTL والنص المختلط وdir=auto.

## Card & Surface

- استخدم البطاقة لتجميع محتوى مرتبط، لا لإحاطة كل عنصر.
- قلل الحدود والظلال.
- إذا كانت البطاقة تفاعلية، اجعل كامل سلوكها واضحًا وقابلًا للوحة المفاتيح.
- لا تجعل البطاقة تبدو قابلة للنقر إذا لم تكن كذلك.

## Navigation

- استخدم تسميات مفهومة وأيقونات معروفة من نظام SVG المعتمد.
- أظهر العنصر الحالي دون الاعتماد على اللون وحده.
- حافظ على ترتيب تنقل منطقي في RTL/LTR.
- لا تكرر أنظمة تنقل متعددة بلا ضرورة.

## Dialog / Sheet

- استخدمها للمهام القصيرة أو القرارات التي تحتاج تركيزًا.
- وفر عنوانًا واضحًا وإجراء إغلاق مفهومًا.
- احترم Escape والتركيز داخل النافذة وإعادته إلى العنصر السابق.
- لا تستخدم dialog لمحتوى طويل يمكن عرضه في صفحة.

## Feedback

- Toast للرسائل العابرة غير الحرجة.
- Inline message للأخطاء التي تؤثر في جزء من الصفحة.
- Dialog للحالات التي تتطلب قرارًا حقيقيًا.
- لا تختفِ رسائل الخطأ المهمة قبل أن يتمكن المستخدم من قراءتها.

## قبل إضافة مكون مشترك جديد

تأكد من وجود نمط متكرر حقيقي عبر أكثر من منتج أو حاجة قوية لإعادة الاستخدام. لا تحول كل تفصيلة خاصة بمنتج إلى مكون مشترك.
