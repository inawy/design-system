# Motion & Accessibility — الحركة وإمكانية الوصول

## الحركة

- الحركة وسيلة توضيح وتغذية راجعة، لا زينة.
- اجعل الانتقالات قصيرة وهادئة؛ نطاق 120–240ms نقطة بداية مقترحة.
- استخدم easing طبيعيًا ومتسقًا.
- لا تحرك عناصر كثيرة في الوقت نفسه.
- لا تجعل الحركة شرطًا لفهم التغيير.
- احترم `prefers-reduced-motion`، وأوقف أو قلل الحركات غير الضرورية.
- تجنب الوميض والحركات المتكررة التي لا يستطيع المستخدم إيقافها.

## إمكانية الوصول

- وفر focus-visible واضحًا لكل عنصر تفاعلي.
- اجعل الوصول لكل وظيفة ممكنًا بلوحة المفاتيح.
- استخدم labels حقيقية للحقول، ولا تعتمد على placeholder وحده.
- استخدم أسماء وصول للأيقونات والأزرار غير النصية.
- لا تستخدم اللون وحده للخطأ أو النجاح أو الاختيار.
- استهدف WCAG 2.2 AA للتباين حيث ينطبق، مع اختبار النصوص والعناصر التفاعلية.
- لا تمنع zoom.
- حافظ على ترتيب تنقل منطقي يوافق ترتيب المحتوى.
- استخدم HTML دلاليًا، وأعلن رسائل الحالة المهمة لقارئات الشاشة عند الحاجة.
- راعِ أهداف لمس مناسبة، واستهدف 44×44 CSS px حيثما أمكن.

## حالات الواجهة

فكر في الحالات المناسبة لكل شاشة:
- Loading / Skeleton عند الحاجة.
- Empty مع شرح وخطوة تالية.
- Error مع سبب مفهوم وإجراء استعادة.
- Success مع تأكيد واضح وغير مبالغ فيه.
- Disabled مع سبب مفهوم عند الحاجة.
- Offline أو Syncing فقط إذا كان المنتج يدعم هذه الحالات فعلًا.
